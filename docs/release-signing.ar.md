# إصدار جيت 2.0.0 كتحديث

معرّف التطبيق باقٍ `app.jeet`، والنسخة 2.0.0 ورقم البناء 5، أعلى من 1.3.0 (4). عنوان WebView ومفتاح البيانات `jeet.v1` باقيان كما في النسخة السابقة. يُرحّل مخطط البيانات عند القراءة ويحافظ على الحصص والقياسات والصور.

## المفتاح المطلوب

يجب استخدام ملف keystore الأصلي الذي وقّع `jeet-1.3.0.apk`. كان إعداد Gradle السابق يستخدم مفتاح debug؛ إذا بُنيت النسخة بالإعداد الافتراضي فهو ملف `.android/debug.keystore` على الجهاز أو بيئة البناء الأصلية. إنشاء ملف جديد بالاسم وكلمة المرور نفسيهما ينتج مفتاحًا مختلفًا، ولا يقبله أندرويد كتحديث. الشهادة الموجودة في APK تتيح المقارنة، لكنها لا تحتوي المفتاح الخاص اللازم للتوقيع.

لم يُعثر على keystore ضمن ملفات المستودع. احفظه خارج GitHub العام، وأضف قيمه في **Settings → Secrets and variables → Actions → Repository secrets**:

فُحص ملف 1.3.0 المنشور فعليًا في [تشغيل تدقيق التوقيع](https://github.com/aalbahrii999/jeet/actions/runs/39817148708). شهادة SHA-256 المطلوبة هي `66783baeda07818b4c063209a34f69bda7588173ccae96c61b3f95cc7aedaf1c`. نجحت قراءة الشهادة، ثم أوقف المسار الإصدار لأن أسرار المفتاح غير مكتملة. تفاصيل النسخة العامة محفوظة في `release/previous-1.3.0.json`؛ هذه شهادة عامة وليست المفتاح الخاص.

| السر | القيمة |
| --- | --- |
| `JEET_SIGNING_KEYSTORE_BASE64` | محتوى ملف keystore الأصلي بترميز Base64 |
| `JEET_SIGNING_STORE_PASSWORD` | كلمة مرور المخزن الأصلي |
| `JEET_SIGNING_KEY_ALIAS` | اسم المفتاح الأصلي داخل المخزن |
| `JEET_SIGNING_KEY_PASSWORD` | كلمة مرور المفتاح الأصلي |

لا تُضف الملف أو كلمات المرور إلى المستودع، أو التعليقات أو سجلات Actions. لا تغيّر المفتاح لكي تنجح مهمة البناء. إذا استُخدم debug الافتراضي دون تعديل، يكون الاسم `androiddebugkey` وكلمتا المرور `android`؛ يلزم مع ذلك **الملف الأصلي نفسه**.

## مسار الإصدار

تشغّل `.github/workflows/release-app.yml` فحص النسخة المنشورة، وتتحقق من SHA-256 المعروف للملف ثم تعرض شهادة توقيعه العامة. توقف النشر إذا غاب المفتاح الأصلي. بعد ضبط الأسرار، شغّل Release Jeet مجددًا أو ادفع commit جديدًا إلى فرع التعديل.

يبني المسار `assembleRelease` دون قابلية التصحيح، ويشغّل اختبارات الترحيل والتخزين والواجهة، ثم يقارن شهادة التوقيع ومعرّف التطبيق ورقم البناء والحد الأدنى لأندرويد بالنسخة السابقة. أي اختلاف غير مقبول يوقف النشر. لا يوجد توقيع debug بديل لإصدار release.

على فرع التعديل، يرفق ملف APK الموقّع ونتيجة المقارنة فقط. بعد الدمج إلى `main` ونجاح الفحص ينشر **v2.0.0 كإصدار مستقر**، مع `jeet-2.0.0.apk` وبصمة الملف وتقرير توافق التحديث. تبقى نسخة 1.3.0 المنشورة كما هي.

## التثبيت مع بقاء البيانات

ثبّت الملف باختيار «تحديث» فوق التطبيق الحالي. لا تحذف التطبيق ولا تمسح بياناته؛ التطبيق لا يعتمد مزامنة سحابية. إن رفض أندرويد التحديث بسبب التوقيع، توقف وتحقق من شهادة النسخة المثبتة؛ لا تعالج ذلك بالحذف. اختبار الترحيل يغطي السجلات والقياسات والصور، أما الاهتزاز والكاميرا فيحتاجان تجربة الهاتف الفعلي.
